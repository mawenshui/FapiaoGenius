# AI 智能发票识别管理系统 - 产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品名称
AI 智能发票识别管理系统（ai_fapiao）

### 1.2 产品定位
面向 Windows 平台的桌面应用，利用 AI 能力智能识别多种格式的发票文件（XML、PDF、OFD），提供发票信息管理、智能凑票、数据导出等功能，帮助用户高效管理报销发票。

### 1.3 目标用户
- 需要处理大量发票报销的企业员工
- 财务人员
- 需要管理发票的 freelancers 和个人用户

### 1.4 核心价值
- **多格式支持**：支持 XML、PDF、OFD 三种主流发票格式
- **AI 智能学习**：遇到无法识别的发票格式，可借助 AI 自动学习并保存解析规则，越用越智能
- **智能凑票**：根据目标金额自动计算最优发票组合方案
- **高效管理**：表格化管理、筛选搜索、批量操作、Excel 导出

## 3. 功能需求

### 3.1 发票导入模块

#### 3.1.1 文件导入
- **支持格式**：`.xml`、`.pdf`、`.ofd`
- **导入方式**：
  - 单个文件选择（文件对话框）
  - 文件夹批量导入（文件夹选择对话框）
  - 支持拖拽文件/文件夹到窗口导入
- **导入过程**：
  - 显示导入进度条
  - 实时显示当前处理文件名
  - 支持取消导入操作

#### 3.1.2 导入结果展示
- **导入结果摘要**：
  - 总文件数、成功数、失败数、跳过数（重复文件）
  - 失败文件列表，每个失败文件以**文件名超链接**形式展示
  - 点击超链接可直接使用系统默认程序打开该文件，便于用户检查发票是否正常
- **失败原因分类**：
  - 文件格式不支持
  - 文件损坏/无法读取
  - 解析规则不匹配（可通过 AI 学习解决）
  - 重复导入（已存在于数据库中）

### 3.2 发票识别引擎

#### 3.2.1 解析规则配置系统
- 所有发票的解析规则均存储在**配置文件**中
- 每种发票类型对应一个独立的配置规则文件
- 配置文件采用 JSON 格式，包含以下信息：
  ```json
  {
    "rule_id": "uuid",
    "rule_name": "铁路12306电子发票",
    "file_format": "pdf",
    "match_pattern": {
      "keywords": ["铁路", "12306", "电子发票"],
      "page_layout": "landscape"
    },
    "extraction_rules": {
      "invoice_number": {
        "type": "regex",
        "pattern": "发票号码[：:]\\s*(\\d+)",
        "region": [100, 50, 400, 80]
      },
      "invoice_date": {
        "type": "regex",
        "pattern": "开票日期[：:]\\s*([\\d]{4}年[\\d]{2}月[\\d]{2}日)",
        "region": [100, 80, 400, 110]
      },
      "buyer_name": {
        "type": "regex",
        "pattern": "购买方[：:]*\\s*名\\s*称[：:]\\s*(.+)",
        "region": null
      }
    },
    "required_fields": ["invoice_number", "invoice_date", "total_amount"],
    "created_at": "2026-06-17T10:00:00",
    "updated_at": "2026-06-17T10:00:00"
  }
  ```

#### 3.2.2 识别流程
```
文件输入 → 格式判断(XML/PDF/OFD)
  → XML: 直接解析 XML 结构
  → PDF/OFD:
      1. 文本提取
      2. 遍历规则库，匹配发票类型（关键词 + 布局特征）
      3. 按匹配到的规则提取字段
      4. 验证必填字段完整性
      5. 成功 → 入库 | 失败 → 标记为失败
```

#### 3.2.3 必填字段（不可修改）
以下字段为系统强制要求识别的字段，用户无法在 AI 学习配置中取消：
- 发票号码（invoice_number）
- 开票日期（invoice_date）
- 不含税金额（amount_without_tax）
- 税额（tax_amount）
- 价税合计（total_amount）

### 3.3 AI 学习模块

#### 3.3.1 入口
- 在**导入结果页面**，对因"解析规则不匹配"而失败的文件，显示 **AI 学习按钮**
- 用户确认发票文件本身没有问题，仅是应用无法识别该格式时，可点击按钮进入 AI 学习页面

#### 3.3.2 AI 连接配置
- 用户需配置以下信息：
  - **API 地址**：AI 服务的 API 端点 URL（默认兼容 OpenAI 接口格式）
  - **API Key**：用户的 API 密钥
  - **模型选择**：支持选择模型，如 `deepseek-chat`（DeepSeek V4 Pro）等
  - 提供**连接测试**按钮，验证配置是否有效

#### 3.3.3 AI 学习流程
1. **上传文件**：将失败的 PDF/OFD 文件内容（文本 + 布局信息）发送给 AI
2. **Prompt 构造**：系统自动构造 Prompt，要求 AI 以**用户配置的格式化结构**返回发票信息
3. **格式化内容配置**：
   - 用户可在 AI 学习页面配置期望的返回格式
   - 必填项（发票号码、开票日期、金额等）锁定，无法取消
   - 用户可添加自定义字段（如部门编号、项目编号等）
4. **AI 返回验证**：
   - 应用自动验证 AI 返回结果是否符合格式要求
   - 必填字段是否完整
   - 金额逻辑是否正确（不含税金额 + 税额 = 价税合计）
   - 验证通过后将结果展示给用户确认
5. **规则保存**：
   - 用户确认后，应用从 AI 返回结果中**自动提取解析规则**
   - 生成该类型发票的配置文件，保存到规则库
   - 下次遇到相同类型发票时，直接使用配置规则解析，无需再调用 AI

#### 3.3.4 AI 学习结果
- 学习成功：提示"已学习新的发票格式：{发票类型名称}"，并展示提取到的规则摘要
- 学习失败：提示失败原因（AI 返回格式错误、必填字段缺失等），允许重试
- 用户可管理已学习的规则（查看、编辑、删除）

### 3.4 发票信息管理

#### 3.4.1 发票信息表格

**表格列定义**：

| 列名 | 字段 | 说明 |
|------|------|------|
| 业务类型 | business_type | 铁路12306、餐饮、住宿、打车、办公用品、通讯、其他等 |
| 发票类型 | invoice_type | 电子发票、增值税专票、增值税普票、机打发票、定额发票等 |
| 发票号码 | invoice_number | 唯一标识，系统自动生成或从发票提取 |
| 开票日期 | invoice_date | 格式：YYYY-MM-DD |
| 购买方 | buyer_name | 购买方名称 |
| 销售方 | seller_name | 销售方名称 |
| 不含税金额 | amount_without_tax | 数值，保留2位小数 |
| 税额 | tax_amount | 数值，保留2位小数 |
| 价税合计 | total_amount | 数值，保留2位小数 |
| 报销状态 | reimbursement_status | 未报销、已报销、报销中 |
| 状态 | status | 正常、异常 |
| 备注 | remark | 用户自定义备注 |

**表格功能**：
- **多选删除**：支持复选框多选，批量删除
- **导出 Excel**：将当前表格数据（支持筛选后的数据）导出为 `.xlsx` 文件
- **分类筛选**：
  - 按业务类型筛选（下拉框）
  - 按发票类型筛选（下拉框）
  - 按报销状态筛选（下拉框）
  - 按状态筛选（下拉框）
  - 按开票日期范围筛选（日期选择器）
- **搜索**：支持按发票号码、购买方、销售方、备注等字段模糊搜索
- **重置搜索**：一键清除所有筛选和搜索条件

#### 3.4.2 发票详情面板
- **触发方式**：点击表格中的某一行，在界面右侧展开详情面板
- **显示内容**：
  - 发票所有字段的完整信息
  - 源文件路径（可点击复制）
  - **打开文件按钮**：点击使用系统默认程序打开发票源文件
  - 识别使用的规则名称
  - 导入时间
- **编辑功能**：
  - 支持在详情面板中编辑：业务类型、报销状态、备注
  - 修改后自动保存到数据库

### 3.5 智能凑票模块

#### 3.5.1 功能入口
- 独立的"智能凑票"页面/标签页

#### 3.5.2 凑票参数配置

| 参数 | 说明 | 选项 |
|------|------|------|
| 目标金额 | 用户期望凑出的总金额 | 数值输入框 |
| 金额模式 | 金额偏差容忍度 | ① 可少于规定金额 ② 可大于规定金额 ③ 相差最小 |
| 挑选策略 | 发票选择偏好 | ① 张数最少 ② 张数最多 ③ 大额优先 ④ 小额优先 |
| 发票范围 | 参与凑票的发票范围 | 可选按业务类型、发票类型、报销状态过滤 |

#### 3.5.3 凑票结果展示
- 以表格形式展示计算结果：
  - 组合方案编号
  - 包含的发票列表（发票号码、金额、业务类型）
  - 组合总金额
  - 与目标金额的差值
  - 发票张数
- 若有多组方案，按挑选策略排序展示
- 支持展开查看每个方案的详细发票列表

#### 3.5.4 一键设置状态
- 用户选中某个凑票方案后，可一键将该方案中所有发票的状态设置为：
  - **报销中**
  - **已报销**
- 设置完成后表格数据同步更新

### 3.6 数据库管理

#### 3.6.1 数据存储
- 使用 SQLite 数据库存储所有发票信息
- 数据库文件位置：应用数据目录（`%APPDATA%/ai_fapiao/`）

#### 3.6.2 数据库操作
- **一键清空数据库**：
  - 入口：设置页面或主菜单
  - 操作前弹出二次确认对话框："确定要清空所有发票数据吗？此操作不可恢复。"
  - 清空后表格自动刷新
- **自动去重**：导入时根据发票号码自动判断是否重复，重复文件跳过并记录

## 6. 非功能需求

### 6.1 性能要求
- 单文件识别响应时间 < 3 秒（不含 AI 调用）
- 批量导入 100 个文件耗时 < 2 分钟
- 表格加载 10000 条数据保持流畅
- 智能凑票计算 1000 张发票耗时 < 5 秒

### 6.2 安全要求
- API Key 加密存储在数据库中
- 发票数据仅存储在本地，不上传任何服务器
- 清空数据库操作需二次确认

### 6.3 兼容性要求
- 支持 Windows 10 / 11
- 支持高 DPI 显示器
- 支持常见的 PDF 版本（1.4 ~ 2.0）

### 6.4 可用性要求
- 支持快捷键操作（Ctrl+O 导入文件、Ctrl+Shift+O 导入文件夹、Delete 删除选中项）
- 操作结果均有明确的提示反馈
- 失败文件可通过超链接快速打开检查
